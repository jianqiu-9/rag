# 固定资料与验收流程

## 1. 数据集

`fixtures/acceptance/v1` 是手工编写的中文合成测试资料，不代表真实企业面试题频率或权威答案。它用于验证约束、改写召回与引用定位；正式上线前仍应补充用户的真实面经。

| 文件 | 内容 |
| --- | --- |
| rag.md | 20 道不同的有答案 RAG 问题，另含一条重复记录 |
| agent.md | 15 道有答案的 Agent 问题 |
| storage.md | 15 道有答案的 MCP/存储问题，5 道无答案问题及普通段落 |
| queries.json | 20 条改写问题、10 条无答案查询、5 条证据不完整查询 |
| manifest.json | 数据版本、原文件及查询 SHA256 |

每条有答案查询保存预期文件、行号和手工编写的答案要点。`calibration` 有 18 条，`acceptance` 有 17 条，均包括三种查询类型；有答案问题两组各 10 条。

样本的预期答案和来源由人工编写的测试真值定义，不从运行中的 LLM 输出反向生成。发布验收前应对这些真值做一次人工复核。修改样本时建立 v2，保留 v1；不要改旧数据后直接覆盖哈希掩盖变化。

```bash
backend/.venv/bin/python scripts/evaluate.py verify-fixtures
```

## 2. 准备专用验收环境

1. 按 README 安装真实 EmbeddingGemma、锁定 SHA，设置真实 DeepSeek Key。
2. 使用独立数据库，不与个人实际面经混在一起。先执行迁移，再通过页面或上传 API 导入三份固定 MD。
3. 等待三份文件全部成功入库，记录 Python、数据库、pgvector、模型配置和机器信息。
4. 检查 query 与文档使用同一指纹，记录上下文预算及切块参数。

## 3. 标定阈值

```bash
backend/.venv/bin/python scripts/evaluate.py calibrate
```

脚本只读取 calibration，扫描 0.1–0.9 阈值，报告有答案问题的过滤后 Recall@8 和负样本仍有候选的比例。只在正样本 Recall@8 ≥90% 的候选阈值中提出建议，不自动改配置。

负样本有候选并不等于回答错误，LLM 还须判断充分性；所以建议值不是最终验收。标定完成后将阈值写入 `.env`，重启后运行独立验收。切块参数或模型配置变更后要重新构建文档向量；仅修改相似度阈值不需要重建。

## 4. 独立验收

```bash
backend/.venv/bin/python scripts/evaluate.py acceptance
```

报告默认写入 `data/reports/acceptance.json`，包含样本版本、模型指纹、阈值、实际回答、预期要点和逐条检查结果。

- 有答案独立问题的过滤后 Recall@8 ≥90%。该指标使用原始候选，不保证预算后所有片段都会进入生成上下文；生成结果另行审查。
- 所有无答案及证据不足问题必须返回 insufficient；服务错误不能算作正确拒答。
- 所有引用必须真实、有效、可定位，答案核心结论必须被引用支持。
- 无原文答案的题目不补写，列题数量不超请求上限。
- 人工逐条核对 actual answer 与 expected_key_points，并检查引用是否支持该结论。即使自动结果通过，overall_acceptance 仍标为 pending_manual_review，不能自动宣称产品已验收。

## 5. 功能用例映射

| PRD 用例 | 自动化覆盖 | 仍需人工/真实模型检查 |
| --- | --- | --- |
| TC-01 上传并查询 | 数据库/API/浏览器完整链路 | 实际中文面经结构与真实召回 |
| TC-02 重复上传 | 哈希去重、不同名相同内容、浏览器重复上传 | 无 |
| TC-03 改写查询 | 固定查询集与评估脚本 | 真实模型 Recall@8 |
| TC-04 不存在资料 | 空库、结构化拒答、页面状态 | 负样本正确拒答率 |
| TC-05 数量不足 | 扩大候选、去重、数量提示 | 真实主题列题覆盖 |
| TC-06 删除再查 | SQL 删除、文件清理、API 及浏览器 | 无 |
| TC-07 重启后索引 | 独立连接读取已保存向量，恢复中断任务 | 正常运行环境完整重启演练 |
| TC-08 非法格式 | API 415、批量部分成功 | 无 |
| TC-09 来源定位 | 行号测试、浏览器原文高亮 | 真实资料中的复杂布局 |
| TC-10 替换 | 失败保留旧版、重试成功激活、并发上传 | 无 |
| TC-11 重启重试 | processing 恢复、尝试号、旧任务迟到保护 | 无 |
| TC-12 原题无答案 | 解析、模型输出拒绝补写、浏览器展示 | 真实模型输出稳定性 |
| TC-13 服务故障 | HTTP Mock 重试、鉴权错误、JSON 错误、API 与页面超时 | 真实供应商连通性 |
| TC-14 并发删除 | 删除阻止迟到入库，来源二次校验 | 无 |
| TC-15 重建调用 | test_audit 对比实际 HTTP payload、原始响应、usage 与最终响应 | 实际供应商联调见 verification |
| TC-16 异常与重试 | 503 重试两条记录、超时、鉴权、非法 JSON、无效引用及原文保留 | 无 |
| TC-17 无模型分支 | 空库、无候选、预算不足均记录原因且无调用行 | 无 |
| TC-18 删除与清理 | 文档删除后快照仍在、按历史版本级联清理、dry-run、时间范围和到期清理 | 备份/导出另行管理 |
| TC-19 恢复与安全 | 活跃租约不误恢复、失租约恢复、写入前后失败、日志边界、秘密脱敏 | 真正进程崩溃只能标记远程结果未知 |

数据库测试与浏览器测试的模型是确定性替身，只验证业务流程。它们不代表真实语义效果、供应商可用性或 PRD 的 P95 指标已经达标。

## 6. 性能记录

在约 1000 道题的专用数据上预热模型，分别记录 Query 编码、数据库检索、生成和端到端耗时的样本量及 P50/P95。不要把首次模型加载混同于预热后的检索延迟；同时保留冷启动记录。

原 PRD 的检索 P95 <1 秒、完整回答 P95 <15 秒是目标，不把远程服务异常从可用性记录中隐藏。若未达目标，先检查批大小、并发、上下文预算及真实调用耗时，再决定是否需要索引或模型优化。
