# MCP 与存储 验收资料

> 人工编写的合成测试资料，不代表真实面试频率或外部权威资料。

## 36. MCP 在工具集成中解决什么问题？
A: MCP 提供客户端与服务器之间连接工具和上下文的协议接口。

## 37. MCP 与 Tool Calling 有什么区别？
A: MCP 关注连接和暴露工具及上下文，Tool Calling 关注模型如何提出结构化工具调用；两者可以配合。

## 38. MCP 服务器可以暴露哪些能力？
A: 本资料讨论工具、资源和提示模板三类能力，调用方应按实际支持能力使用。

## 39. 连接 MCP 工具就意味着可以随意执行吗？
A: 不意味着，执行工具仍受用户授权、能力范围和参数校验约束。

## 40. 如何选择向量数据库的存储边界？
A: 本项目把向量、文档元数据和文本块统一放在 PostgreSQL，向量能力由 pgvector 提供。

## 41. 文件哈希在入库时有什么作用？
A: 文件哈希用于识别完全相同的内容，避免重复建立有效索引。

## 42. 同名文件更新如何保护旧资料？
A: 先处理新版本，全部成功后事务切换；失败时保留旧版本供检索。

## 43. 异步入库为什么要持久化任务状态？
A: 持久化状态便于页面轮询，也能在重启后识别中断任务并重试。

## 44. 如何处理服务重启时未完成的入库？
A: 将遗留处理中任务标记为中断失败，待处理任务继续，失败任务允许手动重试。

## 45. 删除文档应该同时删除哪些内容？
A: 删除逻辑文档的各版本、文本块、向量及原文件副本，并阻止任务重新激活。

## 46. 文件清理为什么需要补偿机制？
A: 文件系统不参与数据库事务，删除失败时可通过持久化清理队列再次尝试。

## 47. 为什么只检索有效文档版本？
A: 只检索有效版本可以避免同时返回新旧答案或已删除资料。

## 48. 请求 ID 对诊断有什么帮助？
A: 请求 ID 关联查询、检索和生成阶段日志，帮助定位一次请求的失败环节。

## 49. 日志为什么默认不保存完整原文？
A: 减少敏感资料泄露，同时保留片段 ID、耗时和错误码用于诊断。

## 50. 如何保证重试不会产生重复有效文本块？
A: 重试前清理未完成数据，并通过数据库约束和事务控制有效版本。
